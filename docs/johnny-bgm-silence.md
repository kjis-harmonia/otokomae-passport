# Johnny予約中のBGM停止漏れ（2026-10-20）

ユーザー実機ではAI予約を開いてもBGMが止まらなかった。従来の停止コミットfb7a837はmain・Staging・releaseにあるが、コードの存在だけでは実機の停止を保証できなかった。

## 再現と原因

旧Staging 20977a6のuseBgmを模擬React／音声で実行し、通常BGMのaudioRefが空の状態で、登録済みの初回登録BGMを再生→Johnnyの停止イベントを送ると再生が続くことを確認した。停止イベントはaudioRefだけをpauseし、全BGMの登録一覧を処理しない。ユーザー端末がこの経路だったかは未確定。

そのほか、イベントを受ける前の画面初期化や遅れて開始するplay、playTrackは、一回限りのpauseをすり抜け得る。実機の古い公開版／別ウィンドウの可能性と、このコード上の不具合は分けて扱う。

## 修正

- 初回登録と通常BGMが使う登録一覧をsrc/audio/bgm.tsへ集約。Johnnyは画面表示前のuseLayoutEffectで直接停止を取得し、閉じるまで保持する。親Hookのイベント購読順に依存しない。
- 登録された全BGMを、再生位置を保ってミュート・一時停止。遅いplay／playingも停止し、新しく作られたBGMも対象にする。Johnnyの声や他の動画・OSの音声は対象外。
- 自動復帰・曲選択でも停止中は再生しない。停止の持ち主がすべて閉じたら、直前に再生していた曲だけ元のミュート状態へ戻して再開を試す。停止／交換した曲は復活させず、保存済みON／OFF設定を保つ。
- 初回登録BGMのplayが一時停止で中断されても、Promiseの拒否を未処理にしない。

## 検証と実機での確認

scripts/bgm-suspension.test.mjsは実際の音声管理モジュールとuseBgmを模擬音声／Reactで読み込み、11件を検査。初回登録BGM、複数曲、遅いplay／playing、後から作る音声、重複する停止、曲停止・交換、元のミュート維持、Johnny音声の非干渉、再開拒否、前面復帰、曲選択を含む。実ネットワーク・有料API・会員DBは使わない。

全回帰テストはnode --experimental-transform-types --test scripts/*.test.mjs。本番の音が止まったという確認ではない。Staging反映後、iPhoneでBGM再生→予約→Johnnyを開く→無音→アプリを前面へ戻しても無音→Johnnyを閉じる、を確認する。初回登録直後のBGMでも同じ確認が必要。OFFの曲が勝手に鳴らないこと、Johnnyの声が聞こえることも確認する。ブラウザーが自動再生を拒否すると閉じた後のBGM再開は手動操作になる。
