# 銀二郎App 実機チェック手順

端末名、OS・ブラウザのバージョン、確認したビルド、日時を記録する。結果は「合格」「不具合」「未確認」のいずれかにする。録画やスクリーンショットには、会員番号・QR・電話番号・氏名を映さない。

## 準備

- 検証用に用意した合成会員で行う。実際のお客様の予約、会員情報、決済は使わない。共有Stagingでの実機試験は利用が承認されたビルドとテストデータでのみ行う。
- 店舗端末・SBの操作は、事前に確認した端末と手順を使う。端末を追加登録せず、PINを試し打ちしない。
- 通知やマイクなどの権限は、それぞれ別に記録する。以前の「許可」のまま進めた場合は、初回の許可画面を未確認とする。会員のセッションを残す更新試験では、サイトデータを消さない。

## iPhone・iPad・Androidのホーム画面追加

1. iPhone／iPadはSafariで開き、共有メニューから「ホーム画面に追加」。AndroidはChrome、続いてSamsung Internetで、ブラウザのメニューから追加する。Androidでアプリ内の案内が出る場合は、案内から開く操作も試す。
2. アイコンとアプリ名を確認し、ホーム画面から起動する。ホーム・会員QR・次回予約が開き、ブラウザのアドレスバーに相当する余白や重なりがないことを確認する。
3. 合成会員でログイン済みの状態にし、別アプリへ切り替えて戻る。完全に閉じてからも起動する。同じ会員のQRと予約が出ることを確認する。Safariのタブと追加後のアプリ間のログイン共有は、合否条件に含めない。
4. オフラインで、開いたままの画面と閉じた状態からの起動を別々に試す。予約操作が成功と表示されないこと、再接続して開くと同じ会員に戻れることを確認する。オフラインで新規起動できることは現行仕様に含まれない。

## 更新と通知

1. 更新前のビルドで合成会員のQRと次回予約を確認し、お知らせを許可する。更新前に模擬通知を1件受け取り、通知センターに残す。
2. 検証先が新版になったあと、旧画面を開いたままにする。操作途中の画面が勝手に閉じないことを確認する。その後、再読み込み、または閉じてからの起動で、検証担当者が示した新版の目印を確認する。必要なら、アプリ切替で戻るだけの場合と、完全終了からの再起動を別々に記録する。
3. 更新前と同じ合成会員のQRと予約が読め、通知の「受け取り中」が維持されることを確認する。更新後にもテスト通知を受け取り、旧通知と新通知を順に押して予約画面への遷移を確認する。
4. 店舗端末とSBを開いた端末で、許可済みの合成SB通知を押す。SBが前に出て、店舗端末の会計や入力が別画面に切り替わらないことを確認する。SBを閉じた状態でも、通知でSBが開くことを確認する。

## 端末の形・入力・権限

| 対象 | 操作と合格条件 |
|---|---|
| 小型／ノッチ付きiPhone、iPad、Android | 縦・横で、QR、予約の人物選択、日付・時刻、確認ボタンを確認。キーボードを開いた状態でも入力と閉じる操作が可能で、下部ナビやホームバーがボタンを隠さない |
| Galaxy Z Fold／Z Flip、Surface Duo系 | 予約の入力途中で開閉する。片側・大画面・2画面表示で入力が保たれ、ヒンジに確認ボタンや案内が隠れない。Windows上の幅変更は実機試験と別に記録する |
| カメラ／マイク | 合成QRで、権限を許可した場合と拒否した場合を別々に確認する。マイクを拒否したときも文字入力を選べる。会話の見た目確認は共通の合成会話を使う |
| ガチャの音声・動画 | 3編をそれぞれ確認し、消音設定の有無、Bluetoothの有無、途中で別アプリに移って戻った場合を記録する。映像の停止、音の二重再生、結果を失わないかを確認する |
| PC Chrome／Edge、Androidタブレット | 幅を縮め、QR、予約、戻る操作、ダイアログを確認する。拡大表示で下部の重要な操作に届くことを確認する |

不具合があったら、画面名・操作直前の状態・再現手順・期待した動作・実際の動作・通信状況を残す。実機で試した手順と、ローカルの模擬試験だけで確認した手順は分けて記録する。
